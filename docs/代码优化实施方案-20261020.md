# 代码优化实施方案

## 目标与实施边界

基于现有 Python/PySide6 + SQLite/Supabase，采用渐进改进，不重写业务、不引入非必要依赖。安装卸载实现已于 2026-10-22 从自研 C#/PowerShell 外壳切换到 Inno Setup 6 原生引擎；r6 正式包只有部分实际验收通过，普通注册卸载/数据链路仍有未解释异常，不能作为完整发布结论。阶段二本地明文传输阻止/遗留入口隔离已验收，云端契约迁移和真实TLS仍未完成；阶段三代码及本地写入退出已验证，真实注册/网络场景未完成；阶段四已建立本地性能基线，未新增性能或架构改写。整体方案尚未全部验收完成，逐项证据见[验收矩阵](优化实施验收矩阵-20261021.md)。既有数据、私有配置、印章和旧发布包保持不变；不重复云数据库初始化、不创建真实账号、不写真实报价。

方案依据为 2026-10-18 审查报告、现有交接记录和 2026-10-20 对直接相关文件的定向复核，不是一次全项目复审；历史测试数量不作为当前通过证据。没有整体性能基线，不承诺臆测的提速百分比。

## 本轮已经实施：安装目录可选

- 安装外壳增加目录输入框和浏览选择，静默安装支持 --install-dir；默认目录不变。
- 支持本地可写的中文/空格路径；拒绝根目录、网络目录、目录链接、无效 Windows 名称、系统保护目录和超过 200 字符的目录。
- 实际路径写入安装状态及 HKCU 卸载登记；桌面、开始菜单和卸载入口引用同一路径。
- 旧安装/同名文件不覆盖；交互卸载先询问是否保留 `data`，“是”保留，“否”只删除 `data`，其他个人文件始终保留。静默卸载默认保留，显式 `/PURGEDATA` 才请求删除；发现链接或属性/枚举失败时保留整份 `data`。换目录不自动迁移旧数据。
- 新包基于未修改的工作 1.7.6 应用，仅重建安装外壳；旧 EXE、旧安装包继续保留。安装后不得直接移动目录，否则状态与卸载登记不一致；迁移须先备份、卸载，再装到新位置。

## 推荐执行顺序

发布门禁小修与安全设计可独立准备；正式新版本发布必须在关键安全风险关闭或明确禁用对应功能后进行。安全相关服务端操作、密钥轮换和真实外部系统验证须另行授权。每阶段先回读上一轮实际写入的文件和直接配置，核对 UTF-8、无 BOM、无截断/乱码、语法/引用；复测通过后才写下一阶段。

### 阶段一：恢复可重复构建

范围：单个 Ruff 导入问题、source/build.ps1、安装器、测试数据准备说明。

1. 在独立输出目录执行现有构建前置检查，只修确认阻塞的导入排序，不批量格式化源码。
2. 把缺私有 seed/原 XLSX 的辅助用例改为自包含最小 fixture；每次只处理确实受影响的用例，不恢复用户业务数据，不降低断言或静默跳过失败。
3. 保留源码检查、定向测试、应用打包、安装包构建及真实安装/卸载为同一发布证据链。正常增量需求仍只跑相关测试；完整正式发布可按其核心影响范围扩大回归。
4. 给安装外壳增加独立发布修订标识和机器可读校验记录，区分同一应用版本的不同安装包；旧包不覆盖。

### 阶段二：收紧安全边界

范围：通用 Supabase 接入、MES 传输、遗留 app.py 入口；不改变报价业务规则。

1. 盘点当前启用的存储模式和调用契约，确认哪些功能实际依赖高权限云密钥。桌面端目标是仅持有公开客户端配置和用户会话，高权限操作放到受限后端；复用现有账号 RPC/接口，不复制另一套权限系统。
2. 对受影响接口补用户身份、成员权限、输入上限、幂等和跨账号拒绝测试。先在授权测试环境验证，再兼容迁移客户端；服务端契约生效后才撤销旧客户端路径。
3. 密钥轮换单独执行、独立授权，核对下游调用者。已撤销的高权限密钥不能作为回滚手段，回滚只能回到仍符合权限边界的客户端版本。
4. MES 先确认服务端证书、域名和 TLS 能力。条件满足后启用 HTTPS 并保持证书校验；不满足则禁用明文登录或由管理员提供经过验证的受控传输方案，不关闭证书校验冒充兼容。
5. 确认 app.py 的直接启动和分发引用；若不再使用则停止分发并显式提示废弃。确需保留时另设计会话与来源校验，普通 GET 不再返回写令牌。不得直接删文件造成隐藏引用断裂。

完成条件：分发物和配置检查无高权限凭据；未授权/跨账号操作被拒绝且合法流程通过；MES 正常 TLS、错误证书、超时及无 TLS 场景结果明确；遗留入口不能被误作为桌面生产入口。依赖：后端与 MES 管理权限和受控测试账号。未具备条件前标记阻塞，不以单元模拟代替真实集成通过。

执行记录（2026-10-21）：已完成本地HTTP请求前阻止、实际Qt提示/密码清空验收以及遗留入口停用和分发排除。r5构建513 passed，源码与冻结HTTP拒绝验收各3项通过、网络请求0；实际归档的账号配置和37个自有Python模块常量未发现高权限凭据。共享Supabase旧配置能力仍待服务端契约生效后迁移，真实跨账号、合法云写入、幂等、正常MES TLS/证书错误/网络超时及密钥轮换均尚未完成。用户补充登录后，已只读确认现用main项目及聚合计数/执行ACL；该项目非空，隔离用途和测试写入范围待确认，未部署或写入。MES新增443入口因证书链不受信任而失败，未发送凭据；后续见[隔离验收执行清单](阶段二隔离验收执行清单-20261021.md)。不能标记阶段二整体完成。最新r5候选未安装/发布，构建及限制见验收矩阵。

### 阶段三：稳定性与故障可诊断

范围：任务退出、备份写入、注册后登录分类、脱敏日志。建议四个小变更分别留可回退边界。

1. 备份优先复用 atomic_bytes 的同卷临时文件、落盘和替换逻辑；按现有大小上限评估内存，不盲目读取超大备份。模拟权限、磁盘写入和替换失败，证明目标是旧完整文件或新完整文件，不出现半写文件；不覆盖真实备份。
2. 明确“关闭到托盘”和“明确退出”两条路径。退出停止新任务，取消可取消读取，异步观察剩余任务；写入完成前保持受控等待和反馈，禁止在 UI 线程无界 waitForDone，也不强杀数据库写线程。实测网络超时和写入进行中退出，核对界面可响应及最终持久化。
3. 注册服务返回成功且拿到 user_id 后，自动登录网络失败应保留“注册已完成，请登录”状态；区分认证失败、网络超时及身份不匹配。注册请求本身结果未知时沿用“先登录核对”的安全路径，禁止自动重提注册。
4. 增加操作阶段、可公开错误码和关联标识；错误文本先经白名单/脱敏，禁止写密码、JWT、API key、Cookie、完整请求体和个人业务内容，保留现有滚动日志限额。

完成条件：故障注入下备份不截断；读取/写入退出不死锁且不丢已承诺写入；注册成功不被引导重复注册；脱敏测试覆盖异常消息和嵌套响应。实际界面与接口验证须对应本轮构建；没有真实外部环境时明确未覆盖。回退按四个小变更分别恢复，数据文件不自动回滚。

### 阶段四：按证据改善维护性和性能

范围：仅上述修改直接暴露的重复逻辑、边界和性能热点，不开展全项目重构。

1. 保持 UI → 服务 → 存储边界，优先提取已经出现重复且测试可覆盖的路径校验、异常分类和原子文件操作；不为减少行数堆通用框架。
