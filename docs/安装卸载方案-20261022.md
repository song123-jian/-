# 安装卸载替换方案与验收

## 目标与决定

目标是提供可自选本地目录、非管理员单用户安装、Windows 原生卸载登记、清晰快捷方式、可重复升级及不误删个人数据的桌面交付。正式安装器由自研 C#/PowerShell 安装外壳替换为 Inno Setup 6；应用业务逻辑与数据格式不变。旧安装器源码保留作历史兼容，不再用来构建默认包。

选择 Inno Setup 的原因是其安装日志、版本化 Setup/Uninstall、Windows 卸载登记、快捷方式管理、静默安装参数和测试生态成熟；不自行维护提权、安装事务、回滚、卸载自删除或注册表兼容层。安装范围为当前 Windows 用户，`PrivilegesRequired=lowest`，不隐式提权。发布包使用独立 `rN` 修订和新的输出目录，不覆盖旧 EXE 或安装包。

## 安装边界

- 默认 `%LOCALAPPDATA%\Programs\PriceQueryDesktop`；向导可选本地固定/可移动磁盘目录，可包含中文、空格和 `&`。
- 校验盘符与本地文件系统、路径长度、Windows 保留名称、尾随点/空格、系统保护目录及每级父目录的 reparse point。拒绝盘符根目录、网络路径、文件碰撞和非专用目录。
- 首装目录限空目录，或仅有一个普通、非链接的 `data` 目录；应用 EXE 被独占方式打开检查，运行/占用时拒绝覆盖或卸载。
- `AppId` 稳定，原生 HKCU Uninstall 子键使用 Inno 的 `_is1` 后缀。实际注册 `InstallLocation`、`UninstallString`、`QuietUninstallString`、显示版本/图标。快捷方式只放在独立开始菜单组，桌面图标默认不选。
- `[Files]` 只接管 EXE、图标、发布清单和安装归属记录；不部署用户 `data`，无递归删除规则。原位升级必须验证登记路径、`ProductId` 和原卸载器；换目录必须先退出并卸载，且不会自动复制数据。
- 检测到仍有 EXE 的旧 C#/PowerShell 登记时不安装、不接管；失效旧登记只记录，不能通过新安装器顺带删除。迁移前应备份数据并优先使用旧安装自己的卸载程序。

## 发布与回滚

1. 从已验收的应用构建输出建立候选，核对 `build-verification.json` 中的入口、应用版本和应用 SHA256。
2. 用官方 Inno Setup 6 编译器构建到不存在的新发布目录；核对 `.release.json` 的版本、安装器修订、引擎、载荷及 Setup SHA256。发布端先在目标目录写唯一临时文件，再以同卷非覆盖改名提交；第二个产物发布失败时撤回本次 Setup，避免留下空清单或单边发布。正式包不可覆盖，测试身份使用独立 QA AppId。
3. 本次按用户明确要求不签名；Windows 可能显示未知发布者或 SmartScreen 提示。签名不作为本轮交付门槛。
4. 在唯一 Windows QA 用户和新本地目录上运行安装器；保留 Setup 日志。逐项核对 HKCU 登记、Windows“已安装的应用”/“程序和功能”列表、开始菜单目标、可选桌面快捷方式、安装 EXE 哈希和应用版本。
5. 启动安装后的真实 EXE，以与安装目录 `data` 不同的隔离目录做有界冒烟验收；验证后关闭应用。
6. 在 `data` 写入合成标记及唯一普通文件并记录 SHA256；在交互卸载中分别选择保留和删除，另验静默默认保留及显式 `/PURGEDATA`。核对 `data` 留存/删除、安装目录其他个人文件始终留存、链接目标不受影响、卸载登记清除和日志。日志、测试数据和报告留存。
7. 完整闭环通过才更新发布元数据为 passed。任一步骤失败标 partial/failed，留存环境、命令、日志和残留登记；不通过静默脚本或删除命令掩盖失败。

回滚时先退出新程序、备份数据和安装日志，通过新包卸载器卸载，再从保留旧版安装包/EXE恢复；用户数据不自动回退或覆盖。若卸载器/登记缺失，停止自动修复，先导出登记及快捷方式信息，评估路径所有权、进程与数据后走单独恢复授权。不得直接递归删除未知安装目录或随意删 HKCU 项。

### r7 卸载个人资料选择

- 交互卸载显示“是否保留个人资料（data 文件夹）”：是为默认并保留，否表示用户明确请求删除；仅删除 `data`，其他非受管个人文件不删除。静默卸载默认保留；`/PURGEDATA` 是显式自动化删除选择。
- 删除前检查整棵 `data`。任何目录属性读取失败、目录枚举失败或发现 reparse point（联接点/符号链接）时，安全地保留整份 `data` 并记录原因；不会尝试递归越过链接删除目标目录。
- QA 实际验收：Windows 11 Pro x64 Build 26200，随机 QA AppId 与最小测试 EXE；交互“是/否”、静默保留、显式删除、链接目标保护及归属/清理覆盖在 `.build/native-personal-data-qa-20261022-final/native-installer-tests.xml`，21 项通过。汇总见 `.build/native-personal-data-qa-20261022-final/verification.json`。
- 新候选 r7：`work/release-native-installer-1.7.6-r7/工作-1.7.6-r7-Setup.exe`，SHA256 `5FF5F4F807283287DD1961DBE9F2B999BA398EA722165CC5934A44EFE0B7738E`；载荷复用已验收 r5（`EF0E1F8D5B801F98A9DF235EBBF428358F1915CA546906D0D349015156DBE52C`）。发布清单为 `not_run`，因为本轮没有用正式 AppId 安装。候选未签名，符合用户决定。

## 未完成与风险

- 正式 r6 的开始菜单 `.lnk` 经 Shell 启动返回“操作已被用户取消”；其后目标目录与安装文件消失，但正式 `PriceQueryDesktop_is1` 登记仍存在。没有卸载日志能解释这一组合状态。随后恢复了本轮纯合成 QA 文件，未恢复程序。禁止重复安装、手工改键或通过其他脚本清理这条正式登记，直到具备明确的恢复授权及可验证方法。
- 本机 Windows 设置“安装的应用”及控制面板“程序和功能”的名称筛选没有显示正式登记条目。登记格式、路径、原生卸载命令、开始菜单快捷方式在注册表/文件层存在，但 OS 列表 UI 可见性未验收通过。
- 旧安装路径 `D:\PriceQuery-QA-20261020-0949\工作 安装` 和其 `data` 在本轮开始前已不存在；旧 `PriceQueryDesktop` 卸载键与两条旧菜单快捷方式残留。两次定向清理请求被执行策略拒绝，之后停止尝试，未通过其它方式绕过。故用户要求的旧安装清理未完成，亦不能称旧数据已保留或恢复。
- 正式 r6 曾出现 Windows Settings/程序和功能未显示、卸载后登记残留；本轮未重装或修改该正式登记。r7 未以正式 AppId 安装，故正式身份下 Windows 列表可见性及同包“安装—卸载—data选择—登记清除”仍**尚未完成验证**。r7 `.release.json` 保持 `verificationStatus=not_run`。

**发布判定：**r7 卸载个人资料选择的代码与隔离 QA 行为已验证，正式包仅为未运行正式身份安装验收的候选。代码签名不属于本轮门槛；是否推进正式身份安装验收，应先单独处理 r6 已观察到的登记/系统列表不确定状态，且不得通过手工改键或绕过限制清理。
